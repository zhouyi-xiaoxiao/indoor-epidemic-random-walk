# The lattice walk against recorded contacts

Section 7.7 of the article and Supplementary Sections S9.2 and S10.3. Contacts generated by the lattice random walk, by a two-zone
walk, by a well-mixed model and by a model with a constant within/between-group ratio are compared with RFID
contact records from six indoor settings (SocioPatterns), in their structure and in the outcome of SIR
epidemics run on them.

| Path | Content |
|---|---|
| `PREREGISTRATION.md`, `PREREG_FREEZE.json` | protocol and freeze record (redacted copies, see `code/REDACTIONS.md`) |
| `FIX_FREEZE.json` | second freeze: the modified (home-anchored) walks and their fitting code, fixed before the three confirmatory datasets were touched |
| `POSTHOC_LOG.md` | every choice made after the first freeze (17 items) |
| `src/a2lib.py`, `pipeline.py`, `sir.c` | loader, contact generators, statistics and tolerances; calibration, prediction and scoring; SIR on a temporal network (compiled on first use with `cc`) |

| `src/fix1.py … fix3rZ.py` | home-anchored walks and their fits |
| `src/03_tables.py`, `show.py` | tables (the figures of the article are drawn by `code/v2_figures.py`) |

| `out/` (link to `data/bsc_validation2/a2_contact_mobility/`) | stored results: `s1_*` (base models, development datasets), `s2a_* … s2d_*` (modified walks, development), `s3a_* … s3d_*` (confirmatory datasets), `ladder.json`, `tables.md`, power |

The contact records are not redistributed. `python code/download_contact_data.py` downloads the ten files
into `data/raw/` and checks their SHA-256.

## Running

```sh
python code/download_contact_data.py
cd code/bsc_validation2/a2_contact_mobility/src
python 00_describe.py
python 01_power.py                                         # synthetic data only
python 02_run.py s1 InVS13,LyonSchool,LH10 WM,BLOCK,RW0,RWhet        # base models, development datasets
python 02_run.py s2b InVS13,LyonSchool,LH10 RWclus fix2               # walks anchored to clustered home sites
python 02_run.py s2d InVS13,LyonSchool,LH10 RWstickO fix3rO           # ... with a slow own seat (and fix3rZ: slow seating zone)
python 02_run.py s3a InVS15,Thiers13,SFHH WM,BLOCK,RW0,RWhet         # confirmatory datasets
python 02_run.py s3b InVS15,Thiers13,SFHH RWclus fix2
python 02_run.py s3c InVS15,Thiers13,SFHH RWstickZ fix3rZ
python 02_run.py s3d InVS15,Thiers13,SFHH RWstickO fix3rO
python 03_tables.py > ../out/tables.md
```

`02_run.py` skips a dataset whose output file exists; move the stored file away to force a run. A run takes
from 20 seconds (office, 2013) to several minutes per dataset. The exact command lines of the stored runs are
in the logs next to the results (`out/*.log`) and in `POSTHOC_LOG.md`.

The re-implementation of the re-check (separately written code, same project) is in `code/checks/contacts/`.

The protocol records of this directory (protocol, addenda, freeze records, the frozen code files and the post-hoc
log) are redacted copies: passages that do not concern the analyses of this article are omitted (marked `[...]`)
or reworded, identifiers are renamed as in the rest of the repository, and in the post-hoc log (and in one line of the
protocol) some labels are written as in the rest of the repository ("re-check" for the second pass, "stretch of
work" for a working period that was interrupted or resumed, the names of the analyses for their labels). Every change is listed, line by line, in
`code/REDACTIONS.md`, with the SHA-256 hashes of the original and of the copy; the hashes of the freeze records
refer to the unredacted originals. The protocol texts call the four analyses of the second set avenues 1 to 4
(A1 further outbreaks, A2 contact records, A3 tracer measurements, A4 zone level) and the first and second sets
of tests rounds 1 and 2; the article does not use these labels.
Where they speak of a "verifier", they mean the re-check of the analysis (separately written code, within the same project
and on the same machine, `code/checks/`), not an independent party, and "the analyst" means the first analysis;
both passes were made by the author. "The memo" means the working notes of the analysis, which are not
distributed; their results are reported in the article.
